Autómata de la agenda

Caso práctico

Juan ha terminado la agenda de la TAREA-02A y funciona: añade contactos, los modifica, los borra y se vacía. María le pide, antes de darla por buena, el diagrama de estado-transición ampliado. —¿Para qué, si ya está hecha? —Para saber qué has programado de verdad. Dime cuántos estados tiene, qué botón se puede pulsar en cada uno y qué pasa en todas las casillas de la tabla, también en las que tu página no deja pulsar. Hay una línea en tu código que no se ejecuta nunca... hasta que alguien escribe la dirección a mano.

Este documento aplica el método de Claude/tema-02/DIAGRAMAS ESTADO-TRANSICION/00-Metodo a la solución de referencia de la TAREA-02A (Agenda), tal como queda en PASO A PASO/paso5-solucion-completa/index.php. El código no se escribió a partir de un autómata: aquí se hace el camino contrario, del código al autómata, que es la mejor manera de revisar una aplicación ya hecha. Todo lo que se afirma está comprobado con PHP 8.2.

1.- Cómo se lee el diagrama

2.- El problema, en resumen

  • Una única página con un formulario (nombre y teléfono) que se envía a sí misma por GET.
  • Si el nombre está vacío, se avisa y no se hace nada más.
  • Si el nombre no está en la agenda, se añade; si ya está, se modifica su teléfono; y si el teléfono llega vacío, el contacto se elimina.
  • La agenda se guarda en campos ocultos del formulario (agenda[nombre]), porque en este tema no hay sesiones ni base de datos.
  • Mientras haya algún contacto se muestra la lista y un enlace Vaciar.

3.- Análisis

  • Eventos entrantes. Tres: la carga de la página sin parámetros, el botón Añadir Contacto (name='enviar') y el enlace Vaciar (?limpiar=1). El botón Limpiar Campos es un type="reset": borra las cajas en el navegador y no llega al servidor, así que no es un evento del autómata.
  • Estados. Dos situaciones en las que la página ofrece cosas distintas, más ST0: con la agenda vacía solo hay formulario; con la agenda con contactos hay además la lista y el enlace Vaciar. Añadir, modificar y borrar no son estados: son lo que pasa al cambiar de uno a otro (o al quedarse).
  • Variables de estado. Una sola: la agenda, un array asociativo nombre => teléfono que viaja en campos ocultos.
  • El estado es implícito. No hay ningún campo estado: el servidor lo deduce de la variable de estado. Si la petición trae agenda, estaba en ST2; si no, en ST1 (o es la primera carga). Vale porque los dos estados solo se diferencian en eso: count($almacenAgenda) > 0.
  • Añadir y modificar son la misma transición. El código no pregunta si el nombre existe: $almacenAgenda[$nombre] = $telefono hace las dos cosas. Por eso no hace falta un predicado «el contacto ya existe».
  • Un predicado que se evalúa después de las acciones. PL2 («quedan contactos») decide el estado siguiente y solo se puede saber después de guardar o borrar: al borrar el único contacto se vuelve a ST1.
  • Una transición que hace el navegador. El enlace Vaciar no envía la agenda (está fuera del formulario): la agenda se vacía porque no viaja. En el servidor, T4 no ejecuta ni una línea propia.

4.- Diagrama de estado-transición ampliado

Desde cualquier estado, cargar la página sin parámetros (escribir la dirección, usar un marcador) lleva a ST0 y de ahí a ST1: la agenda se pierde, porque solo existe en la página que se tenía delante.

6.- Del autómata al código

El autómata está en index.php, pero repartido: no hay switch ni tabla. Cada pieza está aquí (líneas de paso5-solucion-completa/index.php):

LíneasQué es en el autómata

La misma aplicación, escrita a partir del autómata, quedaría así (el estado se sigue deduciendo de la agenda):

const ST1 = 1, ST2 = 2;                                   // agenda vacía, agenda con contactos
const EE_CARGA = 0, EE_ANADIR = 1, EE_VACIAR = 2;
$automata = [                    // Carga Añadir Vaciar
    ST1 => [1, 2, null],
    ST2 => [1, 3, 4],
];

$agenda = is_array($_GET['agenda'] ?? null) ? $_GET['agenda'] : [];   // AC1 o AC0
$estado = count($agenda) > 0 ? ST2 : ST1;                              // VE0, implícita
$evento = match (true) {
    isset($_GET['enviar']) => EE_ANADIR,
    isset($_GET['limpiar']) => EE_VACIAR,
    default => EE_CARGA,
};
$aviso = '';
switch ($automata[$estado][$evento] ?? 1) {               // null ("---") se trata como T1
    case 2:                                               // ---- T2 y T3: Añadir
    case 3:
        $nombre = is_string($_GET['nombre'] ?? null) ? trim($_GET['nombre']) : '';        // AC2
        $telefono = is_string($_GET['telefono'] ?? null) ? trim($_GET['telefono']) : '';
        if ($nombre === '') {                                          // !PL0
            $aviso = 'AVISO: el Nombre es obligatorio';
        } elseif ($telefono !== '') {                                  // PL0 && PL1
            $agenda[ucwords($nombre)] = $telefono;                     // AC3, AC4
        } else {                                                       // PL0 && !PL1
            unset($agenda[ucwords($nombre)]);                          // AC3, AC5
        }
        break;
    case 4:                                               // ---- T4: Vaciar
        $agenda = [];                                                  // ahora sí es una acción del servidor
        break;
}
$estado = count($agenda) > 0 ? ST2 : ST1;                 // PL2: el estado siguiente

Tres diferencias con la solución de referencia, todas a favor de la versión con autómata:

  • Un evento por petición. El match elige uno solo; en el original son dos if seguidos y pueden cumplirse los dos.
  • La variable de estado se comprueba al recuperarla (is_array), y los datos del formulario también (?? null e is_string).
  • T4 es una acción del servidor ($agenda = []), no una consecuencia de lo que el enlace deja de enviar.

7.- Lo que el autómata descubre

La tabla de eventos-estados obliga a pensar en todas las combinaciones, también en las que la página no deja hacer. El navegador solo ofrece los botones de la página; quien escribe la dirección a mano, no. Estas peticiones están probadas contra paso5-solucion-completa con PHP 8.2:

Las dos primeras filas explican el FIXME (pendiente) de la línea 57: con el enlace de la página esa línea no se ejecuta nunca (el enlace no manda la agenda, así que count($almacenAgenda) > 0 es falso), pero es código que parece hacer T4 y en realidad rompe la página. Lo correcto es $almacenAgenda = array();.

Otro detalle que sale al normalizar: ucwords() solo pone en mayúscula la primera letra de cada palabra y deja el resto como está. ANA PEREZ y Ana Perez son dos contactos distintos (comprobado).

9.- Para practicar

  • Añade un predicado PL3 «el teléfono solo tiene cifras» y un aviso si no se cumple. ¿Qué filas de la tabla de transiciones cambian? ¿Hace falta un evento saliente nuevo?
  • Convierte el enlace Vaciar en un botón submit dentro del formulario. ¿Qué llega ahora al servidor? Reescribe T4 con sus acciones.
  • Añade un estado Confirmar entre ST2 y ST1: al pulsar Vaciar se pregunta «¿Seguro?» con dos botones. Dibuja el diagrama y completa la tabla de eventos-estados. ¿Sigue pudiendo ser implícito el estado?
  • Haz que el estado viaje en un campo oculto estado. ¿Qué tendría que comprobar el servidor al recibirlo?
Autoevaluación
  • ¿Por qué añadir y modificar no son dos transiciones distintas? Porque el código hace lo mismo en los dos casos ($almacenAgenda[$nombre] = $telefono) y la página que sale es la misma. Un array asociativo no distingue entre crear una clave y cambiar su valor.
  • ¿Dónde está guardado el estado de la agenda? En ningún sitio: se deduce de la variable de estado. Si llegan campos agenda[...] hay contactos (ST2); si no, la agenda está vacía (ST1).
  • ¿Por qué PL2 se evalúa después de las acciones? Porque pregunta si quedan contactos, y eso solo se sabe después de guardar o de borrar. Al borrar el único contacto, la aplicación vuelve a ST1 y el enlace «Vaciar» desaparece.
  • ¿Qué hace el servidor en T4? Nada propio: el enlace «Vaciar» no envía la agenda y el servidor crea una vacía (AC0), igual que en la primera carga. La línea unset($almacenAgenda) no llega a ejecutarse con la página... y si se ejecuta, da un error fatal.
