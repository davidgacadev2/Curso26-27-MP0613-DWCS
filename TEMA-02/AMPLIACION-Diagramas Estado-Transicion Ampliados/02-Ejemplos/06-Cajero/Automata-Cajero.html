Autómata de un cajero automático

Caso práctico

Una cooperativa de crédito gallega quiere enseñar a sus clientes mayores a usar el cajero, y le pide a BK Programación un simulador web. Carlos cuenta las pantallas: pedir el PIN, el menú, sacar dinero, ingresar, el comprobante, la despedida... y una tarjeta retenida si se equivoca tres veces. —Son ocho situaciones distintas —dice María—, y nueve botones. Sin autómata te vas a perder.

1.- Enunciado

Programa en PHP un simulador de cajero automático de una sola cuenta, sin sesiones ni base de datos (todo lo que hay que recordar viaja en campos ocultos):

  • Al introducir la tarjeta (cargar la página) se pide el PIN (1234). Con el PIN correcto se muestra el menú; con un PIN incorrecto se avisa de los intentos que quedan y, al tercer fallo, la tarjeta queda retenida.
  • El menú permite sacar dinero, ingresar dinero, consultar el saldo y salir.
  • Sacar dinero: un importe múltiplo de 10 € entre 10 y 300 €, que no supere el saldo ni el límite diario de 300 € (sumando lo ya sacado hoy). Ingresar: entre 0,01 y 3.000 €, con dos decimales como mucho. Cada pantalla de importe tiene Confirmar y Cancelar (vuelve al menú).
  • Tras cada operación, un comprobante con el saldo y los últimos 5 movimientos, con Otra operación y Salir. Cancelar en el PIN o Salir muestran la despedida.
  • La cuenta empieza con 250 €. Como el saldo viaja en un campo oculto, va firmado: si alguien lo cambia en el navegador, el cajero lo detecta y retiene la tarjeta.

2.- Análisis

  • Eventos entrantes. Nueve: la carga de la página ("Introducir la tarjeta") y los ocho botones (name="accion"): Aceptar, Retirar, Ingresar, Saldo, Confirmar, Cancelar, Otra operación y Salir.
  • Estados. Ocho. Cada pantalla que espera algo distinto es un estado: el PIN, el menú, el importe a retirar, el importe a ingresar, el comprobante, la tarjeta retenida y la despedida (más ST0). Retirar e ingresar son estados distintos aunque se parezcan: con el mismo botón Confirmar hacen cosas diferentes.
  • Variables de estado. La cuenta (saldo, intentos de PIN, lo retirado hoy y los movimientos) en JSON en un campo oculto, más su firma.
  • Predicados. PL0 (la firma es válida) se comprueba en casi todas las transiciones; los demás son del PIN (PL1, PL2) y de los importes (PL3–PL6). Importante: PL4 (saldo) y PL5 (límite) son distintos porque dan avisos distintos.
  • La firma. hash_hmac('sha256', estado . '|' . cuenta, SECRETO) con una clave que solo conoce el servidor. Quien cambia el saldo no puede calcular la firma nueva. Se firma también el estado, para que no se pueda saltar, por ejemplo, del PIN al menú.
Debes conocer

En una aplicación real nunca se guardaría el saldo en la página: estaría en el servidor (sesión o base de datos, temas 4 y 5). Aquí sirve para practicar la idea de que todo lo que vuelve del navegador puede venir cambiado, y para ver una técnica que sí se usa en la práctica cuando hay que confiar datos al cliente: firmarlos.

Debes conocer

El orden de la cascada decide qué aviso ve el usuario cuando falla más de una cosa: con 200 € de saldo, 150 € ya retirados y una petición de 300 €, fallan PL4 y PL5, pero se avisa del saldo porque PL4 va antes. Es una decisión de diseño: escríbela en la tabla para que el código y la documentación digan lo mismo.

Y un detalle de diseño que salió al probar: con un saldo inicial de 500 € y un límite de 300 €, PL4 nunca podría ser falso (no se puede pedir más de 300). Un camino que no puede darse es una pista de que algo no cuadra; por eso la cuenta empieza con 250 €.

5.- Del autómata al código

Fragmento de solucion/index.php. Cada elseif es una fila de la tabla de T6, en el mismo orden:

case 6:                                                // ---- T6 (ST3, Confirmar)
    $cuenta = recuperarCuenta($estado, $_GET);         // AC1
    $escrito = trim((string) ($_GET['importe'] ?? '')); // AC7: leer el importe
    $euros = filter_var($escrito, FILTER_VALIDATE_INT);
    $importe = $euros === false ? 0 : $euros * 100;
    if ($cuenta === null) {                            // !PL0
        $estado = ST6;
        es6($retenida);
    } elseif ($euros === false || $euros < 10 || $euros > LIMITE_DIARIO / 100 || $euros % 10 !== 0) {   // PL0 && !PL3
        $estado = ST3;
        es3($cuenta, $escrito, 'El importe debe ser un múltiplo de 10 € entre 10 y 300 €.');
    } elseif ($importe > $cuenta['saldo']) {           // PL0 && PL3 && !PL4
        $estado = ST3;
        es3($cuenta, $escrito, 'No tiene saldo suficiente.');
    } elseif ($cuenta['retirado'] + $importe > LIMITE_DIARIO) {   // PL0 && PL3 && PL4 && !PL5
        $estado = ST3;
        es3($cuenta, $escrito, 'Supera el límite diario: hoy puede sacar ' . euros(LIMITE_DIARIO - $cuenta['retirado']) . '.');
    } else {                                           // PL0 && PL3 && PL4 && PL5
        $estado = ST5;
        $cuenta['saldo'] -= $importe;                  // AC5: retirar
        $cuenta['retirado'] += $importe;
        $cuenta = anotar($cuenta, 'Reintegro', -$importe);
        es5($cuenta, 'Retire su dinero: ' . euros($importe));
    }
    break;

La firma (AC1 y AC8):

function firma(int $estado, string $cuentaJson): string
{
    return hash_hmac('sha256', $estado . '|' . $cuentaJson, SECRETO);
}

function recuperarCuenta(int $estado, array $datos): ?array      // AC1: null si PL0 es falso
{
    $json = (string) ($datos['cuenta'] ?? '');
    $recibida = (string) ($datos['firma'] ?? '');
    if (!hash_equals(firma($estado, $json), $recibida)) {
        return null;
    }
    $cuenta = json_decode($json, true);
    return is_array($cuenta) ? $cuenta : null;
}
