Autómata del tres en raya contra el servidor

Caso práctico

Carlos quiere un tres en raya en el que el contrincante sea el servidor. Al dibujar el autómata se atasca: después de que el jugador pulse una casilla, ¿qué evento hace jugar a la máquina? El navegador no envía nada más. María le enseña un truco de los autómatas de protocolos: un evento interno, que no viene de fuera sino que lo produce el propio programa, y que se atiende en la misma petición.

1.- Enunciado

Programa en PHP un tres en raya contra el servidor:

  • Antes de empezar se elige la ficha (X u O) y quién empieza (el jugador o la máquina).
  • Cada casilla libre es un botón. Tras la jugada del jugador, si no ha ganado ni se ha llenado el tablero, juega la máquina en la misma respuesta.
  • La máquina juega así, en este orden: si puede ganar, gana; si no, tapa la jugada ganadora del jugador; si no, el centro; si no, una esquina (0, 2, 6, 8); si no, un lado.
  • La partida termina con victoria, derrota o empate, y se muestra un marcador (ganadas, perdidas y empates) que se conserva entre partidas. Abandonar cuenta como derrota.
  • Al terminar: Revancha (misma configuración) o Cambiar de ficha (volver a la configuración conservando el marcador).
  • La partida viaja en JSON en un campo oculto y se comprueba que es coherente (fichas válidas y que el número de fichas de cada uno cuadra con quién empezó).

2.- Análisis

  • Eventos entrantes. Seis que vienen del navegador (Carga, Empezar, Casilla, Revancha, Abandonar, Cambiar de ficha) y uno interno: turno de la máquina.
  • Estados. Siete: configuración, turno del jugador, turno de la máquina, ganada, perdida y empate (más ST0). ST3, el turno de la máquina, es un estado transitorio: nunca se envía al navegador. Cuando una transición termina en ST3, el programa atiende enseguida el evento interno (T4), que deja el autómata en ST2, ST5 o ST6.
  • Predicados de la jugada. PL5 (la jugada del jugador gana) y PL6 (llena el tablero) se calculan antes de poner la ficha, sobre el tablero con la ficha "imaginada". Igual PL7 y PL8 para la máquina.
  • El orden importa. Si una jugada gana y a la vez llena el tablero (la novena ficha), es victoria: PL5 se comprueba antes que PL6.
  • Coherencia (PL3). Un tablero XXX------ con el jugador X que empezaba es imposible (tres X y ninguna O): la partida se ha manipulado.

5.- Del autómata al código

El switch va dentro de un bucle do ... while. Si una transición termina en ST3, el bucle vuelve a entrar con la transición del evento interno (T4). Así el programa sigue la tabla de eventos-estados también para los eventos que no vienen del navegador:

do {
    $interno = false;
    switch ($transicion) {
        // ... T1, T2, T3 (pueden terminar en ST3)
        case 4:                                            // ---- T4 (ST3, Interno: turno de la máquina)
            $maquina = contraria($p['ficha']);
            $jugada = jugadaMaquina($p['tablero'], $maquina);   // AEs PRE: AC9
            $pl7 = haceTresEnRaya($p['tablero'], $jugada, $maquina);
            $pl8 = seLlena($p['tablero']);
            $p['tablero'][$jugada] = $maquina;             // AC10: poner la ficha de la máquina
            if ($pl7) {                                    // PL7
                $estado = ST5;
                $p['marcador']['perdidas']++;              // AC11
                fin($p, 'Ha ganado la máquina');
            } elseif ($pl8) {                              // !PL7 && PL8
                $estado = ST6;
                $p['marcador']['empates']++;               // AC8
                fin($p, 'Empate');
            } else {                                       // !PL7 && !PL8
                $estado = ST2;
                es2($p);
            }
            break;
        // ... T5, T6, T7
    }
    // Evento interno: si la máquina tiene el turno, se atiende ya, en esta misma petición
    if ($estado === ST3) {
        $transicion = $automata[ST3][EE_INTERNO];
        $interno = true;
    }
} while ($interno);
Debes conocer

Al leer el estado de la página, el programa rechaza ST3 (lo trata como ST0): ese estado no puede venir del navegador, porque nunca se le envía. Es la misma idea que las celdas --- de la tabla, pero para un estado entero.

6.- Pruebas

Como la máquina juega siempre igual, se pueden preparar partidas completas y comprobar cada tablero (31 peticiones):

Partida Jugadas (jugador → máquina) Caminos Resultado
X, empieza el jugador 0→4, 8→2, (4 ocupada), 6→3, 7 T3 → T4 (sigue) ×3, T3 !PL4, T3 PL5 gana el jugador (la máquina no puede tapar la doble amenaza)
revancha 4→0, 1→7, 2→6, 3→8 T5, T3 → T4 ×3, T4 PL7 gana la máquina
revancha 4→0, 2→6, 3→5, 8→1, 7 T3 → T4 ×4, T3 !PL5 && PL6 empate (el jugador llena el tablero)
O, empieza la máquina (máquina 4), 0→2, 6→3, 5→8, 1→7 T2 PL2 → T4, ..., T4 !PL7 && PL8 empate (la máquina llena el tablero)
revancha y Abandonar (máquina 4) T5 PL2 → T4, T6 perdida; marcador 1 / 2 / 2
tablero XXX------ en el campo oculto — T3 !PL3 "La partida no era válida"
estado=3 en la URL — ST0 → T1 configuración

7.- Para practicar

  • Añade un nivel fácil en el que la máquina juegue en una casilla libre al azar. ¿Cambia el autómata o solo la acción AC9? ¿Siguen valiendo las pruebas?
  • Haz que la máquina "piense" en dos pasos internos: primero decidir y mostrar "La máquina está pensando..." y luego jugar. ¿Cuántos estados transitorios harían falta? ¿Tiene sentido si todo ocurre en la misma petición?
