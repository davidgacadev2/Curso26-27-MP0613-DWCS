Autómata del asistente de reservas del Bar Baio

Caso práctico

El Bar Baio quiere que sus clientes reserven mesa desde la web, paso a paso: primero los datos, luego la fecha y la hora y por último cuántos son. Al final, un resumen para comprobarlo todo. Uxía, la dueña, insiste: —Si en el resumen alguien ve que se ha equivocado de día, que pueda cambiarlo sin volver a escribir todo. Carlos se da cuenta de que el botón Siguiente ya no siempre lleva al paso siguiente.

1.- Enunciado

Programa en PHP un asistente de reservas en tres pasos y un resumen, sin sesiones (lo que no se pide en un paso viaja en campos ocultos):

  • Datos: nombre (de 2 a 60 letras) y teléfono (9 cifras que empiezan por 6, 7, 8 o 9).
  • Fecha y hora: desde mañana hasta dentro de 30 días; el bar cierra los lunes y los domingos no hay cenas. Horas: 13:30, 14:30 (comidas), 20:30 y 21:30 (cenas).
  • Comensales y zona: de 1 a 12, en interior o terraza; en la terraza, 6 como mucho por reserva; y tiene que haber plazas libres en esa franja (cada franja tiene 20 plazas; las ya ocupadas se simulan con una fórmula que depende del día y de la hora).
  • Resumen, con un botón Editar en cada bloque. Al editar un paso, Siguiente vuelve directamente al resumen. Si se cambia la fecha a una franja sin plazas para los comensales que ya había, se pasa al paso 3 con un aviso.

Cada paso tiene Atrás (sin perder lo escrito) y Cancelar. Al confirmar se vuelven a comprobar todos los datos (los ocultos se pueden haber cambiado) y se muestra un código de reserva.

2.- Análisis

  • Eventos entrantes. Seis: Carga, Siguiente, Atrás, Editar (con el número de paso: editar:2), Confirmar y Cancelar.
  • Estados. Siete: un estado por paso (ST1–ST3), el resumen (ST4), confirmada (ST5) y cancelada (ST6), más ST0.
  • Una variable de estado que cambia el camino. $editando (PL2): se pone a cierto al pulsar Editar (AC5) y vuelve a falso al llegar al resumen (AC4). Con el mismo evento Siguiente en el mismo estado ST1, el nuevo estado es ST2 o ST4 según PL2.
  • Predicados en cascada. El paso 2 tiene cuatro (la fecha existe, está en plazo, ese día abre, la franja es válida ese día) y cada uno solo tiene sentido si se cumplen los anteriores: no se puede saber si es lunes si la fecha no existe.
  • Un predicado que depende de otro paso. PL10 (hay plazas) necesita la fecha y la franja (paso 2) y los comensales (paso 3). Por eso aparece en T4 y también en T3 cuando se edita la fecha.
  • Fechas. Todo se calcula a partir de "hoy" con DateTimeImmutable y la zona horaria Europe/Madrid; la fecha llega del <input type="date"> como AAAA-MM-DD y se comprueba que existe (el 31 de febrero no vale).

4.4.- Comprobación de predicados (T3)

Siete caminos. Los cuatro primeros forman una cascada (cada uno supone ciertos los anteriores); PL2 y PL10 solo se miran con una fecha y una franja válidas:

PL3 PL4 PL5 PL6 PL2 PL10 Camino
0 x x x x x aviso de fecha
1 0 x x x x aviso de plazo
1 1 0 x x x aviso de lunes
1 1 1 0 x x aviso de hora
1 1 1 1 0 x paso 3 (ST3)
1 1 1 1 1 1 resumen (ST4)
1 1 1 1 1 0 paso 3 con aviso de plazas (ST3)
Debes conocer

Dos caminos de T3 llevan al mismo estado (ST3) con distinta salida y distintas acciones: el normal y el de "faltan plazas" tras editar. No es un error: el estado dice qué espera la página (los comensales), la salida dice qué se le muestra al usuario. Y en el segundo camino AC4 apaga $editando: el usuario tiene que pasar otra vez por el paso 3, y su Siguiente (T4) ya lleva al resumen por su propio camino.

5.- Del autómata al código

Fragmento de T3 en solucion/index.php, con los siete caminos en el orden de la tabla. Cada predicado es una función con nombre (plFechaValida, plFechaEnPlazo...), así el if se lee casi como la tabla:

case 3:                                                // ---- T3 (ST2, Siguiente)
    if (!plFechaValida($r['fecha'])) {                 // !PL3
        $estado = ST2;
        paso2($r, ['Elija una fecha.']);
    } elseif (!plFechaEnPlazo($r['fecha'])) {          // PL3 && !PL4
        $estado = ST2;
        paso2($r, ['La fecha debe estar entre mañana y dentro de ' . DIAS_ANTELACION . ' días.']);
    } elseif (!plAbre($r['fecha'])) {                  // PL3 && PL4 && !PL5
        $estado = ST2;
        paso2($r, ['Los lunes el Bar Baio está cerrado.']);
    } elseif (!plFranja($r['fecha'], $r['franja'])) {  // PL3 && PL4 && PL5 && !PL6
        $estado = ST2;
        paso2($r, ['Elija una hora' . (fecha($r['fecha'])->format('w') === '0' ? ' de comida (los domingos no hay cenas).' : '.')]);
    } elseif (!$editando) {                            // PL3..PL6 && !PL2
        $estado = ST3;
        paso3($r);
    } elseif (plPlazas($r['fecha'], $r['franja'], (int) $r['comensales'])) {   // PL3..PL6 && PL2 && PL10
        $estado = ST4;
        $editando = false;                             // AC4
        resumen($r);
    } else {                                           // PL3..PL6 && PL2 && !PL10
        $estado = ST3;
        $editando = false;                             // AC4: hay que revisar el paso 3
        paso3($r, ['En esa franja solo quedan ' . plazasLibres($r['fecha'], $r['franja']) . ' plazas: cambie los comensales o vuelva atrás.']);
    }
    break;

7.- Para practicar
