Autómata de una máquina expendedora

Caso práctico

El instituto quiere poner una máquina de bebidas en la cafetería y el profesor de la asignatura le pide a Carlos que simule su programa en PHP antes de comprarla. Juan le cuenta lo que no se ve desde fuera: la máquina tiene que saber dar el cambio con las monedas que tiene, no solo calcularlo. —Si no tiene monedas de 10 céntimos, ese café no lo puede vender.

1.- Enunciado

Programa en PHP una máquina expendedora (sin sesiones: el estado de la máquina viaja en un campo oculto):

  • Productos: agua (0,80 €, 3 unidades), café (1,10 €, 2), zumo (1,50 €, agotado) y bocadillo (2,35 €, 1). Monedas aceptadas: 5, 10, 20, 50 céntimos, 1 € y 2 €. El cajón para el cambio empieza con una moneda de 50, una de 20, dos de 10 y dos de 5 céntimos.
  • Se elige un producto (si está agotado o no existe, se avisa). Después se van introduciendo monedas hasta llegar al precio; una moneda no aceptada se devuelve.
  • Al llegar al precio, si se puede dar el cambio exacto con las monedas del cajón (incluidas las que se acaban de introducir), se entrega el producto y el cambio; si no, se devuelve todo el dinero ("No hay cambio suficiente").
  • Cancelar devuelve lo introducido. En las pantallas de entrega y de devolución hay que pulsar Recoger.
  • Mantenimiento: con la clave 2468 se entra en un panel que muestra existencias y monedas y permite reponer (5 unidades de cada producto y 5 monedas de cada tipo).
  • Si el campo oculto llega manipulado, la máquina se reinicia.

2.- Análisis

  • Eventos entrantes. Nueve. Elegir y Moneda llevan un dato (qué producto, qué moneda): van en el valor del botón, accion=elegir:cafe, accion=moneda:200.
  • Estados. Siete: esperando selección, esperando el pago, producto entregado, dinero devuelto, pidiendo la clave y mantenimiento (más ST0). "Entregado" y "devuelto" son estados distintos porque muestran cosas distintas, aunque desde los dos solo se pueda Recoger.
  • Variables de estado. La máquina entera en JSON: existencias, monedas del cajón, producto elegido y monedas introducidas.
  • Predicados. El más interesante es PL5: se puede dar el cambio. No basta con restar: hay que buscar una combinación con las monedas que hay. Coger siempre la moneda más grande no funciona con monedas limitadas (60 céntimos con una de 50 y tres de 20: tras la de 50 faltan 10 y no hay; con tres de 20 sí sale), así que la búsqueda retrocede si no encuentra.
  • PL0 en todas las transiciones (menos T1): si el JSON no es coherente (faltan productos, cantidades negativas, monedas que no existen), la máquina se reinicia.

3.- Diagrama de estado-transición ampliado

La caja discontinua "ST3, ST4" representa los dos estados: Recoger hace lo mismo en los dos. La flecha "cualquiera, !PL0" desde STx resume el primer camino de todas las transiciones T2–T9.

5.- Del autómata al código

Fragmento de solucion/index.php. Observa que PL3 y PL4 se calculan antes de cambiar nada, y que AC4 (añadir la moneda) se hace en tres de los cuatro caminos:

case 3:                                                // ---- T3 (ST2, Moneda)
    $moneda = filter_var($dato, FILTER_VALIDATE_INT);  // AC2: leer la moneda
    $precio = PRODUCTOS[$m['producto']][1];
    $pl3 = in_array($moneda, MONEDAS, true);           // PL3: moneda aceptada
    $creditoTotal = array_sum($m['credito']) + ($pl3 ? $moneda : 0);
    $pl4 = $pl3 && $creditoTotal >= $precio;           // PL4: llega al precio
    if (!$pl3) {                                       // PL0 && !PL3
        $estado = ST2;
        es1($m, 'Moneda no aceptada: se la devolvemos.');
    } elseif (!$pl4) {                                 // PL0 && PL3 && !PL4
        $estado = ST2;
        $m['credito'][] = $moneda;                     // AC4
        es1($m);
    } else {
        $m['credito'][] = $moneda;                     // AC4
        $cajon = $m['cajon'];                          // las monedas introducidas también sirven para el cambio
        foreach ($m['credito'] as $c) {
            $cajon[$c]++;
        }
        $cambio = buscarCambio($creditoTotal - $precio, $cajon);
        if ($cambio !== null) {                        // PL0 && PL3 && PL4 && PL5
            $estado = ST3;
            // AC5: cobrar, entregar y dar el cambio (ver el fichero)
            es2($m);
        } else {                                       // PL0 && PL3 && PL4 && !PL5
            $estado = ST4;
            $m['bandeja'] = $m['credito'];             // AC6: devolver el crédito
            $m['producto'] = null;
            $m['credito'] = [];
            es3($m, 'No hay cambio suficiente');
        }
    }
    break;

La búsqueda del cambio (PL5), recursiva y con vuelta atrás:

function buscarCambio(int $cambio, array $disponibles, int $desde = 0): ?array
{
    if ($cambio === 0) {
        return [];
    }
    for ($i = $desde; $i < count(MONEDAS); $i++) {
        $moneda = MONEDAS[$i];
        if ($moneda <= $cambio && $disponibles[$moneda] > 0) {
            $disponibles[$moneda]--;
            $resto = buscarCambio($cambio - $moneda, $disponibles, $i);
            if ($resto !== null) {
                return [$moneda, ...$resto];
            }
            $disponibles[$moneda]++;
        }
    }
    return null;
}
// buscarCambio(60, [200 => 0, 100 => 0, 50 => 1, 20 => 3, 10 => 0, 5 => 0])  ->  [20, 20, 20]

7.- Para practicar

  • Añade "Elegir otro producto" mientras se paga, conservando el crédito. ¿Qué celda de la tabla deja de ser ---? ¿Qué pasa si el crédito ya supera el precio del nuevo producto?
