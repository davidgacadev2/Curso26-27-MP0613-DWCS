Autómata de la Tarea 02B: juego de tablero con letras ocultas

Caso práctico

La tarea del tema es un juego: un tablero con un rombo de asteriscos que esconden las letras de una palabra. Carlos ha visto las tres soluciones de ejemplo y en todas la lógica está repartida entre if, variables primeraVez, finJuego... María le reta a hacerlo con un autómata: —Es el mejor ejercicio para ver que funciona: tiene cinco situaciones distintas y tres cosas que puede hacer el jugador.

1.- Enunciado (resumen de los requisitos)

  • La página pide la longitud del lado del tablero y una palabra, con los botones Enviar y Borrar. Se comprueba que el lado es un número impar entre 5 y 30 y que la palabra tiene 5 letras como mínimo; si no, se muestra cuál es el error.
  • Con datos correctos aparece el tablero: las casillas del borde muestran o y sobre ellas se dibuja un rombo de asteriscos. Las letras de la palabra se esconden al azar debajo de los asteriscos (si no caben, la palabra se recorta).
  • Cada asterisco es un botón. Si esconde una letra: +5 puntos, el asterisco se cambia por la letra y esa letra desaparece de la caja de texto de la palabra. Si no: −2 puntos y un fallo seguido más.
  • El marcador aparece en cuanto se pulsa el primer asterisco.
  • El juego termina al acertar todas las letras o al cuarto fallo seguido; entonces se muestra un mensaje y el tablero queda deshabilitado.
  • Todo el estado de la partida (el tablero, las letras, la palabra, los puntos, los fallos) se guarda en campos ocultos.

2.- Análisis

  • Eventos entrantes. Tres: la carga de la página (también el enlace Borrar, que lleva a la página sin parámetros), Enviar la configuración y pulsar un asterisco (Jugada, con el valor fila x columna).
  • Estados. Cinco. ST0 carga y ST1 configurando, como siempre. Después, el tablero recién creado (ST2) y el tablero con jugadas (ST3) son estados distintos porque la página muestra cosas distintas: el marcador solo aparece desde la primera jugada. Y ST4, fin de la partida, porque ahí los asteriscos ya no se pueden pulsar.
  • Variables de estado. La partida entera viaja en campos ocultos: el lado, el tablero (*, o o la letra descubierta), las letras escondidas, la palabra que queda, los puntos y los fallos seguidos.
  • Predicados de la configuración. Tres atómicos: lado entre 5 y 30 (PL0), lado impar (PL1), palabra de 5 letras o más (PL2). Separarlos permite dar el aviso concreto de cada error.
  • Predicados de la jugada. La jugada es válida (PL3: la partida recuperada de los ocultos es coherente y la casilla es un asterisco sin descubrir), la casilla esconde una letra (PL4), era la última letra (PL5), ya llevaba 3 fallos seguidos (PL6). PL5 y PL6 se evalúan antes de actualizar los puntos: describen la situación de la que se parte, y así todos los predicados se comprueban antes de las acciones.

Debes conocer

En ST2 dos de los caminos de T3 no pueden darse nunca: la palabra tiene al menos 5 letras (PL5 es falso: no puede ser la última) y aún no hay fallos (PL6 es falso). Desde ST2 solo se llega a ST3 (o a ST1 si la jugada no es válida). No hace falta una transición distinta para ST2: los mismos if sirven, y esos caminos simplemente no se toman. Es un buen ejemplo de invariante: algo que se sabe cierto en un estado y que el diagrama ayuda a descubrir.

5.- Del autómata al código

Fragmento de T3 en solucion/index.php. Los predicados PL5 y PL6 se calculan antes de las acciones AC6 y AC7, que cambian $palabra y $fallos:

case 3:                                                    // ---- T3
    $partida = recuperarPartida($_GET);                    // AC1
    $jugada = sscanf((string) $_GET['jugada'], '%dx%d');   // AC2
    [$f, $c] = is_array($jugada) ? $jugada : [null, null];
    $pl3 = $partida !== null && $partida['fallos'] !== false && is_int($f) && is_int($c)   // PL3: jugada válida
        && ($partida['tablero'][$f][$c] ?? '') === '*';
    if (!$pl3) {                                           // !PL3
        $estado = ST1;
        es0();
        break;
    }
    $pl4 = isset($partida['letras'][$f][$c]);              // PL4: esconde una letra
    $pl5 = strlen($partida['palabra']) === 1;              // PL5: era la última
    $pl6 = $partida['fallos'] === FALLOS_MAXIMOS;          // PL6: llevaba 3 fallos
    if ($pl4) {
        // AC6: descubrir la letra, quitarla de la palabra, +5 puntos, fallos a 0
        if (!$pl5) {                                       // PL3 && PL4 && !PL5
            $estado = ST3;
            es3($partida);
        } else {                                           // PL3 && PL4 && PL5
            $estado = ST4;
            es4($partida);
        }
    } else {
        // AC7: -2 puntos, un fallo más
        if (!$pl6) {                                       // PL3 && !PL4 && !PL6
            $estado = ST3;
            es3($partida);
        } else {                                           // PL3 && !PL4 && PL6
            $estado = ST4;
            es5($partida);
        }
    }
    break;
Recomendación

recuperarPartida() (AC1) es la parte más larga de la solución, y no por casualidad: toda la partida vuelve del navegador y se puede cambiar. Comprueba que el lado es válido, que cada casilla tiene el valor que le corresponde según el rombo (o fuera, * o una letra dentro), que las letras escondidas están dentro del rombo y que la palabra que queda tiene exactamente las letras que siguen escondidas. Si algo no cuadra, devuelve null y la jugada no es válida (PL3 falso). En el tema 5, con las sesiones, la partida se guardará en el servidor y esta comprobación será mucho más sencilla.

7.- Para practicar

  • Añade un botón Rendirse que muestre todas las letras y termine la partida. ¿Desde qué estados se puede pulsar? Añade la columna a la tabla de eventos-estados y su transición.
  • El enunciado dice "más de 3 fallos seguidos". Cambia el límite a una constante configurable: ¿qué predicado cambia? ¿Cambia la comprobación de predicados?
  • Haz que el marcador se vea también en ST2 (con 0 puntos). ¿Siguen haciendo falta ST2 y ST3, o se pueden juntar? Redibuja el diagrama.
